# React + TypeScript + Vite

This template provides a minimal setup to get React working in Vite with HMR and some Oxlint rules.

Currently, two official plugins are available:

- [@vitejs/plugin-react](https://github.com/vitejs/vite-plugin-react/blob/main/packages/plugin-react) uses [Oxc](https://oxc.rs)
- [@vitejs/plugin-react-swc](https://github.com/vitejs/vite-plugin-react/blob/main/packages/plugin-react-swc) uses [SWC](https://swc.rs/)

## React Compiler

The React Compiler is not enabled on this template because of its impact on dev & build performances. To add it, see [this documentation](https://react.dev/learn/react-compiler/installation).

## Expanding the Oxlint configuration

If you are developing a production application, we recommend enabling type-aware lint rules by installing `oxlint-tsgolint` and editing `.oxlintrc.json`:

```json
{
  "$schema": "./node_modules/oxlint/configuration_schema.json",
  "plugins": ["react", "typescript", "oxc"],
  "options": {
    "typeAware": true
  },
  "rules": {
    "react/rules-of-hooks": "error",
    "react/only-export-components": ["warn", { "allowConstantExport": true }]
  }
}
```

See the [Oxlint rules documentation](https://oxc.rs/docs/guide/usage/linter/rules) for the full list of rules and categories.

## Голосовые сообщения и медиа

- Кнопка микрофона записывает голосовое сообщение через `MediaRecorder`; перед отправкой запись можно отменить.
- Поддерживаются изображения, MP4/WebM/MOV-видео, аудио, PDF, TXT/CSV, ZIP и документы Microsoft Office.
- Максимальный размер одного вложения — 25 МБ.
- Тип, исходное имя, размер и длительность голосового хранятся в `messages.attachment_meta`.
- Миграция колонки выполняется автоматически при запуске сервера.

## Хранение загруженных файлов

Аватары, голосовые и остальные вложения сервер кладёт в `UPLOADS_DIR` (по умолчанию `server/uploads`).
На хостингах с одноразовой файловой системой — Railway, Render, Fly — эту папку **обязательно**
нужно вынести на постоянный том, иначе при каждом деплое все загруженные файлы исчезают,
а в базе останутся ссылки на несуществующие картинки.

Как сделано на Railway: к сервису подключён том с точкой монтирования `/data`, а переменная
окружения задана как `UPLOADS_DIR=/data/uploads`.

```bash
railway volume add -m /data
railway variables --set UPLOADS_DIR=/data/uploads
```

Если картинка всё же не загрузилась, интерфейс показывает букву вместо значка битого
изображения (`src/components/AvatarImage.tsx`).

## Звонки

Один на один, WebRTC, аудио и видео.

**Что умеет**

- Приглашение приходит на все открытые вкладки, но как только звонок принят на одном
  устройстве, остальные перестают звонить, а сигналинг идёт только в принявший сокет.
- Пока идёт звонок, второй входящий автоматически получает «занято» — это проверяет сервер,
  а не только клиент.
- Камеру и демонстрацию экрана можно включить прямо в аудиозвонке: у соединения всегда есть
  видео-трансивер, а повторные переговоры идут по схеме perfect negotiation.
- Собеседник видит, что у вас выключен микрофон или камера и что вы показываете экран
  (событие `call_state`).
- Звонок можно свернуть в плашку и продолжать переписываться; медиаэлемент при этом
  не пересоздаётся, поэтому звук не прерывается.
- Микрофон, камеру и динамики можно выбрать заранее в настройках или переключить на лету
  во время разговора — дорожка подменяется без разрыва соединения.
- Индикатор качества связи считается по `getStats` (задержка, потери, битрейт), рядом
  показывается, кто говорит.
- Горячие клавиши: `M` — микрофон, `V` — камера, `Esc` — свернуть/развернуть.
- Пока идёт разговор, экран не гаснет (Wake Lock), а входящий звонок при скрытой вкладке
  подсвечивается в заголовке и системным уведомлением.

**История звонков**

Каждый звонок оставляет запись в чате: исходящий/входящий с длительностью, пропущенный,
отклонённый, отменённый. Записи создаёт сервер (`server/src/calls.js`), поэтому итог не зависит
от того, у кого раньше закрылась вкладка: обрыв сокета тоже корректно завершает звонок.
Записи хранятся в `messages` с `type = 'call'` и JSON-полем `call_meta`; миграция добавляется
автоматически при старте сервера.

### Настройка TURN-сервера

Аудио/видеозвонки используют WebRTC. По умолчанию доступны только публичные STUN-серверы Google — этого достаточно в большинстве сетей, но звонок может не установиться, если оба собеседника находятся за строгим NAT/симметричным файрволом (частая ситуация в мобильных и корпоративных сетях). Чтобы это исправить, добавьте на сервере (`server/`) переменные окружения TURN-релея:

```
TURN_URLS=turn:turn.example.com:3478,turns:turn.example.com:5349
TURN_USERNAME=имя_пользователя
TURN_CREDENTIAL=пароль_или_токен
```

- `TURN_URLS` — один или несколько адресов через запятую.
- Если переменные не заданы, сервер отдаёт клиентам только STUN — звонки продолжат работать как раньше.
- Учётные данные никогда не попадают в клиентский бандл: клиент получает список ICE-серверов с бэкенда через `GET /api/ice-servers` при каждом запуске.

Получить TURN-сервер можно, например, у [Twilio](https://www.twilio.com/docs/stun-turn), [Cloudflare Calls](https://developers.cloudflare.com/calls/), [Metered.ca](https://www.metered.ca/tools/openrelay/) (есть бесплатный лимит) или развернуть свой [coturn](https://github.com/coturn/coturn).

При кратковременных обрывах сети звонок пытается восстановиться сам: звонящая сторона запускает ICE restart, и есть 15 секунд на восстановление, прежде чем звонок завершится. В интерфейсе в этот момент видно «Восстановление соединения…».

### Email-алерты о падениях и подборе пароля

Сервер может слать письмо владельцу при аварийном завершении процесса (`uncaughtException`)
и при срабатывании блокировки аккаунта после подряд идущих неудачных попыток входа —
похоже на подбор пароля. Использует ту же почтовую инфраструктуру (`RESEND_API_KEY`/`MAIL_FROM`),
что и письма пользователям.

```
ALERT_EMAIL=you@example.com
```

Если переменная не задана — алерты просто не отправляются (сервер продолжает работать как раньше).
На каждый вид события — не чаще одного письма в 10 минут, чтобы не заспамить себя во время атаки.

### Двухфакторная аутентификация (TOTP)

Пользователи могут включить вход по коду из приложения-аутентификатора (Google Authenticator,
Aegis и похожие) в Настройки → Безопасность. Секрет хранится в базе зашифрованным
(AES-256-GCM) — для этого серверу нужен 32-байтный ключ:

```
TOTP_ENC_KEY=<64 hex-символа или 44 base64-символа>
```

Сгенерировать ключ:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

Если переменная не задана — попытка включить 2FA вернёт понятную ошибку, остальной
функционал не затрагивается. **Ключ нельзя менять после того, как хотя бы один пользователь
включил 2FA** — иначе существующие секреты станет невозможно расшифровать, и им придётся
подключать 2FA заново.
