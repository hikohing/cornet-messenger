# CorNet Desktop (Windows)

Electron-обёртка, которая открывает окно сразу на выбранном (по health-check) зеркале
сервера — точно как обычный браузер открывает сайт. SPA-фронтенд не зашивается в `.exe`
и не дублируется отдельно: приложение всегда показывает ту версию, что реально отдаёт
сервер. Список зеркал с health-check и failover даёт приложению шанс продолжить
работать, если текущий адрес заблокирован по DPI — без пересборки `.exe`.

**Почему не локальный сервер + отдельный origin для API** (более ранний вариант):
вся авторизация в проекте — один httpOnly-cookie с `SameSite=Lax`. Такая cookie не
отправляется в кросс-origin fetch/WebSocket запросах браузера — только при прямых
переходах по ссылке. Поэтому SPA и API обязаны быть на одном origin; открывать окно
сразу на реальном адресе сервера — единственный вариант, который не ломает эту cookie.

## Сборка

```bash
cd desktop
npm install           # подтянет Electron (~150-250 МБ, нужен интернет)
npm run start          # локальный прогон без упаковки, для проверки
npm run build           # → desktop/release/: Connecto Setup <version>.exe (NSIS) и Connecto <version>.exe (portable)
```

Сборка `dist/` в корне репозитория для этого не нужна — desktop-клиент ничего не
бандлит из фронтенда, только открывает окно на живом сервере.

Без code signing — при первом запуске Windows SmartScreen покажет предупреждение
«неизвестный издатель». Это ожидаемо, не баг; платный сертификат подписи — отдельный
будущий шаг.

## Список зеркал (`resources/mirrors.default.json`)

```json
{
  "version": 1,
  "mirrors": ["https://web-messenger-production-3f4e.up.railway.app"],
  "remoteUpdateUrl": null
}
```

- `mirrors` — адреса бэкенда, которые перебираются по очереди при старте и при потере
  соединения (health-check через `GET /api/health`). Пользовательская runtime-копия
  живёт в `%APPDATA%/Connecto/mirrors.json` и только дополняется, никогда не
  затирается полностью — даже если сеть с обновлениями недоступна, старые зеркала
  остаются рабочими.
- Когда появится свой домен за Cloudflare — просто добавь его вторым элементом в
  `mirrors` и пересобери `.exe` (или используй `remoteUpdateUrl` ниже, чтобы обновить
  уже установленным клиентам без пересборки).
- `remoteUpdateUrl` (опционально) — стабильный HTTPS URL, отдающий JSON вида
  `{ "mirrors": ["https://..."] }` (например raw-файл в своём публичном GitHub-репозитории/
  gist). Приложение периодически подтягивает его в фоне и добавляет новые адреса
  к локальному списку. Это best-effort вспомогательный канал, а не единственная точка
  отказа — локальный список работает сам по себе.

## Известное ограничение: звонки без своего TURN

Сигнализация (WebSocket) устойчива к блокировкам за счёт зеркал. Сама аудио/видео
дорожка (WebRTC/RTP) — отдельное соединение; сейчас ICE использует только публичный
Google STUN (`server/src/ice.js`), TURN на Railway не настроен. Это значит прямое
P2P-соединение между собеседниками, которое может не устанавливаться под строгим NAT
или агрессивным DPI. Если это станет проблемой — единственное решение — свой TURN-релей
(`TURN_URLS`/`TURN_USERNAME`/`TURN_CREDENTIAL` в Railway env, см. корневой `README.md`).

## Гарантии

Устойчивость к блокировкам — это гонка технологий, а не разовая настройка. Список
зеркал и health-check снижают риск полного отказа, но не гарантируют обход любых
будущих блокировок.
